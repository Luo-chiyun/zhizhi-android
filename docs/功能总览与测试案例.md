# 功能总览与测试案例

对应版本：**0.1.7**（versionCode 8）

---

# 第一部分：功能总览

## 一句话定位

不做强制锁机，屏幕上没有常驻计时器，也不会替你把应用关掉。
它只做一件事：**在你可能走神的时候，问一句"你进来时想做什么"。** 答案永远由你给。

## 三条不可动摇的约束

1. **没有联网权限。** 不声明 `android.permission.INTERNET`，这是系统强制的物理隔离。
   识别、计时、统计全部在本机，连应用名都不记，只记次数和总时长。
2. **不使用 AccessibilityService。** 前台识别只用 `UsageStatsManager`。
3. **不强制。** 应用无法、也不会替你关闭别的应用。

## 界面与入口

底部三个 tab：**首页 / 记录 / 设置**。
子页面从首页的「功能模块」网格进入；顶栏左上角的圆形按钮、或系统返回手势（左右边缘向内滑），
都退回上一级。

### 首页（仪表盘）

| 区域 | 内容 |
| --- | --- |
| 头部 | 日期 + 「知止不殆」+ 当前状态（未开启 / 不在学习时段 / 休息中·剩余 m:ss / 已暂停至 hh:mm / 监测进行中） |
| 主控卡片 | 总开关（缺权限时直接跳权限页，而不是启动一个必定失败的服务）+ 「休息 N 分钟」／「结束休息」 |
| 三列统计 | 今日提醒 / 拦回 / 监测时长；前两项带「较昨日 ±N」趋势 |
| 功能模块 | 2 列网格：监控哪些应用、休息计时器、本地记录、其他个性化设置、诊断、权限检查、关于与打赏 |
| 学习时段 | 开关 + 起止时间（点按钮调系统时间选择器，支持跨午夜） |
| 提醒阈值 | 连续使用多久后第一次提醒（1–30 分钟） |
| 底部 | 《道德经·第四十四章》箴言 |

### 记录（tab）

三列统计卡（提醒次数 / 选择退出 / 累计监测）+ 「明细」分组（再看一会儿、正在做正事、
游戏前放弃、别再提醒、一键回桌面成功/尝试、卡片显示/降级）+ 「逐日」列表 + 清空按钮。
可切近 7 天 / 近 30 天。

### 设置（tab）= 其他个性化设置

| 分组 | 项目 |
| --- | --- |
| 提醒节奏 | 重复提醒间隔（0–30 分钟，0 = 一次停留只提醒一次）、重新进入该应用时的冷却（0–10 分钟）、"我正在做正事"的冷静期（5–60 分钟） |
| 休息 | 休息默认时长（5–60 分钟）、休息结束时点"再休息"的时长（1–30 分钟） |
| 卡片与游戏 | 进入游戏前先确认一次（开关）、提醒卡片位置（顶部 / 底部） |
| 后台与退出 | 开机自动恢复监测（开关）、退出后清掉该应用的后台（**Android 14+ 上禁用并标注"本机不支持"**） |
| 暂时停止监测 | 安静地停 30 分钟，到期**不**叫你（与"休息"相对） |

### 子页面

**监控哪些应用**：默认全部"不监控"。可一键套用预设名单（78 条，先与本机已装列表求交集），
可按"全部 / 已选"筛选、搜索。每个应用**四态**选择：

| 状态 | 含义 |
| --- | --- |
| 不监控 | 明确不管它（套用预设不会覆盖这个决定） |
| 不影响学习 | 知道它是工具而非消遣：词典、网课、AI 助手、办公、微信 / QQ |
| 娱乐 | 超时后温和提醒 |
| 游戏 | 启动前确认一次，局内静默 |

只有「娱乐」和「游戏」会被计时与提醒。

**休息计时器**：滑杆选时长（默认取设置里的休息默认时长）+ 开始休息；休息中显示倒计时和"结束休息"。

**诊断**：活体指标（主循环心跳 / 当前判定 / 本进程累计记录）、环境（包名版本机型、
四项权限、提醒通道真实重要性、服务与锚点状态）、一票否决开关清单、
一键「测试提醒卡片（前台）」、**事件记录（单块可选文本，上限 1000 条）**、
「复制完整诊断到剪贴板」。

**权限检查**：四项权限逐卡说明用途 + 状态徽标 + 厂商后台设置跳转。

**关于**：名字来源与出处、隐私声明、GPL-3.0、版本号、打赏二维码、源码地址。

### 提醒卡片（悬浮窗，三种）

**① 娱乐类温和提醒**

```
知止不殆。你进来时想做什么？
小红书 · 已连续 1 分 12 秒
[ 已完成，退出 ]                        ← 主按钮，通栏
[ 我走神了，退出 ]  [ 再给 5 分钟 ]      ← 2 列
[ 我正在做正事 ]    [ 别再提醒这个应用 ]  ← 2 列，最后一个更轻
```

**② 游戏启动前确认**

```
知止不殆 · 即将入局
原神 · 你确定现在要开始吗？
[ 算了，退出 ]   [ 确定，开始玩 ]
```
回答之后**整局静默**——避免局内弹窗断触。

**③ 休息结束**

```
知止不殆 · 休息有度
休息时间过了，请继续努力哦
[ 好的，现在开始 ]   [ 再休息 5 分钟 ]
```

### 通知（三条通道，全部无声无振动）

| 通道 | 重要性 | 用途 |
| --- | --- | --- |
| `zhizhi_monitor` | MIN | 前台服务常驻通知。会在通知栏最底部被折叠，不在状态栏显示图标 |
| `zhizhi_alerts` | **HIGH** | **卡片弹不出来时的降级通道**：同样的选项，以横幅形式出现 |
| `zhizhi_service_low` | LOW | 缺权限、回到桌面被拦截之类的兜底提示。平时通知数恒为 0 |

常驻通知上有一个动作按钮，随状态变化：
「休息 N 分钟」→（休息中）「结束休息」→（已暂停）「恢复监测」。

## 运行时参数

| 项目 | 值 |
| --- | --- |
| 轮询间隔（学习时段内） | **1 秒** |
| 轮询间隔（时段外 / 屏幕关闭） | 20 秒 |
| 屏幕状态与系统重新对齐 | 5 秒一次；屏幕广播路径**强制**重算，不受节流 |
| 卡片可见性探测 | 0 / 350 / 800 / 1600 / 2600 ms 阶梯，任一次通过即算成功 |
| "一键回到桌面"实测 | 1.5 秒后回查前台是否已改变 |
| 监测时长落盘 | 每满 1 分钟 |
| 诊断事件上限 | 内存 1000 条；磁盘保留最近 200 条，每 2 秒最多写一次 |
| 单次 tick 计入上限 | 5 秒（防止主循环被调度卡住时把 3 秒算成 3 分钟） |

## 明确做不到的（不要当成 bug）

| 做不到 | 为什么 |
| --- | --- |
| 强制关闭别的应用 | 没有无障碍权限发不了返回键，也不打算申请 |
| **清掉别的应用的后台进程** | **Android 14 起系统禁止**（`killBackgroundProcesses` 官方文档：第三方应用只能结束自己的进程）。Android 13 及以下可用 |
| 0 延迟拦截游戏启动 | `UsageStatsManager` 事件本身有 0.5–2 秒延迟。加上 1 秒轮询，总延迟约 2 秒 |
| 在隐藏悬浮窗的应用上弹卡片 | Android 12 起应用可调 `setHideOverlayWindows(true)`。此时走降级通知 |
| 识别工作资料（Work Profile）里的应用 | 跨用户查询使用情况在普通权限下不可行 |
| 保证在所有国产 ROM 上都活着 | 厂商后台清理策略不公开且逐版本变化，需要真机实测 |

# 第二部分：完整测试案例

一个约 40 分钟的场景，覆盖全部功能与两条降级路径。
每一步都写了**预期现象**和**应该在诊断记录里看到什么**——两者都符合才算通过。

> 全程只需要：手机 + 已装 0.1.7 的 APK。
> 诊断记录在首页 →「诊断」→「事件记录」点「展开」；也可以点「复制完整诊断到剪贴板」贴给我。

## 阶段 0：准备（5 分钟）

**把设置调成下面这样，后面的预期时间才是确定的：**

| 位置 | 项目 | 设为 |
| --- | --- | --- |
| 首页 | 学习时段 | **关掉「只在设定时段内监测」**（变成全天，避免测试刚好落在时段外） |
| 首页 | 首次提醒阈值 | **1 分钟** |
| 个性化设置 → 提醒节奏 | 重复提醒间隔 | **5 分钟** |
| 个性化设置 → 提醒节奏 | 重新进入该应用时的冷却 | **0（不冷却）** |
| 个性化设置 → 提醒节奏 | "我正在做正事"的冷静期 | **2 分钟**（方便验证，不用等 15 分钟） |
| 个性化设置 → 休息 | 休息默认时长 | **5 分钟** |
| 个性化设置 → 休息 | 再休息时长 | **1 分钟** |
| 个性化设置 → 卡片与游戏 | 进入游戏前先确认一次 | **开** |
| 个性化设置 → 卡片与游戏 | 卡片位置 | **顶部** |
| 首页 | 总开关 | **开** |

**分类**（首页 →「监控哪些应用」）：确认至少勾了 **小红书**（娱乐）和 **王者荣耀或原神**（游戏）。
没勾就点「一键套用预设名单」。

然后回首页 →「诊断」→ 点「复制完整诊断到剪贴板」存一份，这是**基线**。

## 阶段 1：基础（3 分钟）

| # | 操作 | 预期 | 诊断记录里应该看到 |
| --- | --- | --- | --- |
| 1.1 | 打开诊断页 | 「主循环心跳」这个数字**每秒都在涨** | `[Loop]` 行周期性地出现 |
| 1.2 | 看「环境」区 | 悬浮窗=是、使用情况访问=是、服务运行中=是、锚点窗口可见=是 | — |
| 1.3 | 看「提醒通道（横幅）」 | **高（会弹横幅）**。如果不是，页面会出现红色警告块 | — |
| 1.4 | 点「测试提醒卡片（前台）」 | 卡片**立刻**出现在屏幕顶部，8 秒后自动消失 | `[Test] 开始自检…` → `[Overlay] 卡片已添加 … thread=main` → `[Card] showCard -> ADDED` → `[Card] 可见性确认 attached=true … size=WxH` → `[Test] 自检卡片已移除` |
| 1.5 | 上一条里的 `size=` | 宽×高都不是 0，且**高在 600–700 左右**（不是 1000+） | — |

## 阶段 2：娱乐类提醒的五个出口（10 分钟）

依次做 2.1 → 2.5，每次都重新进入小红书。

> 每次进入后**等满 1 分钟**。如果上一次的卡片没消失，说明你没退出去。

| # | 操作 | 预期 | 诊断记录里应该看到 |
| --- | --- | --- | --- |
| **2.1 已完成，退出** | 进小红书 → 等 60 秒 → 点「已完成，退出」 | 卡片消失，**回到桌面** | `[Nudge] 第 1 次提醒 app=小红书 pkg=com.xingin.xhs 已用=60s` → `[Card] showCard -> ADDED` → `[Answer] DONE_EXIT` → `[Exit] 回到桌面成功` |
| **2.2 我走神了，退出** | 重进 → 等 60 秒 → 点「我走神了，退出」 | 同上，回到桌面 | `[Answer] DISTRACTED` → `[Exit] …` |
| **2.3 再给 5 分钟** | 重进 → 等 60 秒 → 点「再给 5 分钟」 | 卡片消失，**留在小红书**（不会回桌面）；**5 分钟内不再弹** | `[Answer] SNOOZE`，之后 5 分钟内**没有**新的 `[Nudge]` 行 |
| **2.4 我正在做正事** | 重进 → 等 60 秒 → 点「我正在做正事」 | 卡片消失，留在小红书；**2 分钟内不再弹**（因为阶段 0 把冷静期设成了 2 分钟） | `[Answer] WORKING`，之后 2 分钟内没有新的 `[Nudge]` |
| **2.5 别再提醒这个应用** | 用 **QQ**（预设里也是娱乐类）重进 → 等 60 秒 → 点「别再提醒这个应用」 | 卡片消失，**留在 QQ**（不回桌面）。去「监控哪些应用」搜 QQ，应显示为**不监控** | `[Answer] MUTE_APP` → `[Answer] 不再提醒 com.tencent.mobileqq，已加入忽略名单` |

**本阶段的关键验证点**：2.5 之后再在 QQ 里待 10 分钟，**不应该**有任何提醒，
且 `[Loop]` 里的 `cat=` 应该从 `ENTERTAINMENT` 变成 `IGNORED`。

**还要验证"同一次停留只问一次"**：在 2.1 里，卡片弹出来之后**先别点**，
停留 3 分钟。预期：**只有一张卡片**，不会因为"我还没点"而被追加第二张。

## 阶段 3：游戏（8 分钟）

| # | 操作 | 预期 | 诊断记录里应该看到 |
| --- | --- | --- | --- |
| **3.1 启动即确认** | 打开王者荣耀（或原神） | **约 2 秒内**弹出确认卡片（在加载画面上，不是局内） | `[Loop] … fg=com.tencent.tmgp.sgame cat=GAME card=false` → `[Game] 游戏前确认 app=王者荣耀` → `[Card] showCard -> ADDED` |
| **3.2 局内静默** | 点「确定，开始玩」，打进一局，玩 5 分钟 | 整局**没有任何弹窗**；触摸、技能释放完全正常 | 5 分钟内**没有**新的 `[Game]` / `[Nudge]` 行 |
| **3.3 反复重进每次都弹** | 退出游戏，**重新打开** | **又一次**弹出确认 | 新的 `[Game] 游戏前确认 app=…` |
| **3.4 同一停留不重复问**（本次修复的重点） | 在 3.3 弹出的卡片上点「算了，退出」，然后**什么都不做，等 10 秒** | 最多弹**一次**。**不应该**出现"点完之后 0.4 秒又弹一张" | `[Answer] GAME_CANCEL` 之后，10 秒内**没有**第二条 `[Game]` 行 |
| **3.5 退出是否生效** | 看 3.4 之后去了哪 | 两种结果都算通过：<br>• 回到桌面 → `[Exit] 回到桌面成功`<br>• 还在游戏里 → `[Exit] 回到桌面未生效 started=true left=false target=…` + 一条可点的兜底通知 | 看 `[Exit]` 那一行判断走了哪条路 |

> 3.4 是 0.1.7 修的那个 bug 的回归测试：以前 `onAnswer` 会把会话清空，
> 而"一键回桌面"要 1.5 秒才生效，这期间前台还是游戏 → 下一 tick 建出新会话 → 立刻再问一遍。
> 现在会话不会被清，所以同一次停留里只问一次。

## 阶段 4：休息（7 分钟）

| # | 操作 | 预期 | 诊断记录里应该看到 |
| --- | --- | --- | --- |
| **4.1 从通知栏开始休息** | 下拉通知栏 → 展开常驻通知 → 点「**休息 5 分钟**」 | 通知栏文字变成「休息中，HH:MM 后提醒你回来」；动作按钮变成「结束休息」。首页状态行显示「休息中 · 剩余 m:ss」 | `[Break] 从通知开始休息` |
| **4.2 休息期间完全不打扰** | 立刻打开小红书，待 3 分钟 | **一次提醒都没有** | `[Loop] monitor=off 原因=休息中（到 …）` |
| **4.3 到点弹卡片** | 等满 5 分钟 | 弹出卡片：标题「休息结束」，正文「**休息时间过了，请继续努力哦**」，两个按钮「好的，现在开始」「**再休息 1 分钟**」 | `[Break] 休息结束，弹回来提醒` → `[Break] 弹休息结束卡片` |
| **4.4 再休息** | 点「再休息 1 分钟」 | 卡片消失；**1 分钟内不再打扰**；1 分钟后**再次**弹出同一张卡片 | `[Answer] BREAK_EXTEND` → 1 分钟后 `[Break] 休息结束，弹回来提醒` |
| **4.5 好的，现在开始** | 点「好的，现在开始」 | 卡片消失，**立刻恢复监测** | `[Answer] BREAK_BACK` |
| **4.6 无视卡片不会被永久挡住** | 再休息一次，到点后**不点任何按钮**，等 2 分钟 | 卡片可能还挂着，但**监测已经恢复**：此时进小红书等 1 分钟，应该能拿到提醒 | `[Break] 休息结束，弹回来提醒` 之后有正常的 `[Nudge]` |

## 阶段 5：暂停与时段（4 分钟）

| # | 操作 | 预期 | 诊断记录里应该看到 |
| --- | --- | --- | --- |
| **5.1 安静暂停** | 个性化设置 →「暂时停止监测 30 分钟」 | 首页状态行变成「已暂停，至 hh:mm 自动恢复」；通知栏也显示暂停 | `[Loop] monitor=off 原因=已暂停至 …` |
| **5.2 暂停期间不提醒** | 进小红书待 2 分钟 | 没有任何提醒 | 同上，没有 `[Nudge]` |
| **5.3 立刻恢复** | 首页 →「立即恢复监测」 | 状态回到「监测进行中」 | `[Loop] monitor=on …` |
| **5.4 时段外不监测** | 首页 → 学习时段 → 把开始时间设成"1 分钟后"，结束时间设成"2 分钟后" | 时段外 `[Loop]` 显示「不在学习时段」；进入时段后开始正常监测 | `[Loop] monitor=off 原因=不在学习时段 HH:MM–HH:MM` → 到点后 `[Loop] monitor=on …` |
| **5.5 测完记得改回来** | 学习时段 → 关掉开关（恢复全天） | — | — |

## 阶段 6：锁屏与解锁（2 分钟）

| # | 操作 | 预期 | 诊断记录里应该看到 |
| --- | --- | --- | --- |
| **6.1 锁屏暂停** | 进小红书 → 按电源键锁屏 → 等 30 秒 → 解锁 | 锁屏期间不计时、不提醒 | `[Loop] monitor=off 原因=屏幕未点亮或未解锁` |
| **6.2 解锁后立刻恢复** | 解锁后立刻看诊断页 | 应该在**1–2 秒内**就恢复可监测，不是等十几秒 | `[Service] 屏幕状态重新对齐 → 可监测（interactive=true locked=false）` |

> 6.2 是 0.1.6 修的问题：以前解锁广播会撞上 5 秒节流被吞掉，
> 之后主循环还要等 20 秒的 `SLEEP_TICK`，实测出现过解锁后 17 秒才恢复。

## 阶段 7：降级路径（可选，但值得做一次，5 分钟）

这条路径平时很难触发，但它是"提醒不会丢"的保证，值得主动验一次。

| # | 操作 | 预期 | 诊断记录里应该看到 |
| --- | --- | --- | --- |
| **7.1 临时关掉悬浮窗权限** | 系统设置 → 应用管理 → 知止 → 权限 → 关掉「悬浮窗」 | — | — |
| **7.2 触发一次提醒** | 进小红书等 1 分钟 | **卡片不会出现**，但会收到一条**横幅通知**，内容含「提醒卡片没显示出来，改用这条通知」+ 副标题「原因：悬浮窗权限对该应用未生效」，并且带同样的动作按钮 | `[Card] showCard -> NO_PERMISSION` → `[Card] 悬浮窗不可用（悬浮窗权限对该应用未生效），降级为横幅通知` |
| **7.3 横幅上直接操作** | 在横幅上点「我走神了，退出」 | 回到桌面 | `[Service] 收到来自通知的回答：DISTRACTED` → `[Answer] DISTRACTED` → `[Exit] 回到桌面成功` |
| **7.4 恢复权限** | 系统设置里把「悬浮窗」打开，回诊断页点「刷新」 | 悬浮窗=是；再点自检卡片能正常弹出 | — |

## 阶段 8：收尾自查（2 分钟）

打开首页 →「本地记录」，对着下面这张表核对。数字不必完全相等（你可能多测了几次），
但**每一行都应该有数**，且没有明显矛盾：

| 项目 | 本次测试大致应该是 |
| --- | --- |
| 提醒次数 | ≥ 8（阶段 2 五次 + 阶段 3 三次 + 阶段 4 一次） |
| 选择退出 | ≥ 2（2.1、2.2） |
| 选择再看一会儿 | 1（2.3） |
| 选择正在做正事 | 1（2.4） |
| 游戏前放弃 | ≥ 2（3.2 之前那次、3.3、3.4） |
| 选择"别再提醒这个应用" | 1（2.5） |
| 累计监测时长 | 应该有两三分钟以上 |
| "一键回到桌面"成功 / 尝试次数 | 两个数都 > 0；**如果成功数是 0**，说明你这台机器拦了后台启动 Activity，去看 `[Exit]` 那几行的 `started/left` |
| 提醒卡片实际显示 / 降级为通知 | 阶段 7 之前应该全是"显示"；阶段 7 期间会多出降级 |

## 快速失败对照表

出问题时先查这张表，能省一轮来回：

| 现象 | 先看哪一行 | 大概率原因 |
| --- | --- | --- |
| 卡片完全没出现 | `[Card] showCard ->` | `NO_PERMISSION` = 悬浮窗权限没生效；`FAILED` = addView 抛异常（看后面的类名）；有 `ADDED` 但下一行"探测 N 次仍不可见" = 窗口被系统藏了 |
| 卡片出现但位置不对 | `[Overlay] 卡片已添加 … atBottom=` | 跟「卡片位置」设置对不对 |
| 该提醒却什么都没发生 | `[Loop] monitor=off 原因=` | 那一行直接写了为什么没在监测（总开关/休息/暂停/时段/锁屏/权限） |
| 前台应用识别错 | `[Loop] … fg= cat=` | 包名对不对、判成的分类对不对 |
| 提醒来了但没有横幅 | 诊断页「提醒通道（横幅）」 | 不是"高（会弹横幅）"就按页面上的红字改系统设置 |
| 点按钮没反应 | `[Answer]` | 没有这行 = 点击没到；有这行但没后续 = 看动作对应的 `[Exit]` / `[Break]` 行 |
| 服务好像没在跑 | 诊断页「主循环心跳」 | 数字不涨 = 服务没起来；涨 = 服务正常，问题在别处 |
