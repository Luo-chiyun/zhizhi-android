# 开发路线图

按“能在真机上用起来”倒推，不是按代码量排序。每个阶段结束都有一个可验证的东西。

**当前状态：1.0.4。阶段 0–4 基本完成，正在做阶段 3（日常可靠性）。**

## ✅ 阶段 1：验证三个“系统会不会答应我”的前提

| # | 要验证的事 | 结论 |
| --- | --- | --- |
| 1 | `startActivity(HOME)` 能不能把用户从别的应用送回桌面 | **成立**。前提是有悬浮窗权限（它是后台启动 Activity 的豁免条件之一）。已加 1.5 秒回查兜底 |
| 2 | Android 15 上锚点窗口能不能让后台起前台服务成功 | **成立，但顺序不能错**：必须先挂 1×1 锚点窗口，再 `startForeground()`。反了就抛 `ForegroundServiceStartNotAllowedException` |
| 3 | 游戏启动后 1 秒内能不能识别到 | **部分成立**。`UsageStatsManager` 事件是异步写入的，有 0.5–2 秒延迟。所以“启动前确认”实际是在加载期弹的，不是 0 延迟拦截 |

## 🚧 阶段 3：让它抗得住日常（进行中）

开源工具和玩具的分界线。这一阶段主要靠你在真机上跑一段时间。

* **电量实测。** `adb shell dumpsys batterystats --charged app.zhizhi` 对比开 / 关监测的一天耗电差异。目标：< 2%/天。
* **国产 ROM 的存活率。** 至少在小米、华为、OPPO、vivo 四家各测一台。这一步不通过，
  用户装完第二天就会发现它“不工作了”。**已在 OPPO / ColorOS（Android 16）上验证通过**，其余三家待测。
* **多用户 / 工作资料边界。** 工作资料（Work Profile）里的应用目前识别不到，需要在文档里说明。
* **时区与跨日。** 学习时段用“当天第几分钟”，不吃时区；跨 `23:59→00:00` 需要实测一次。
* **长时间驻留。** 连续开着几天，观察通知栏按钮状态、统计聚合、诊断日志是否正确。

## 阶段 5：之后可以考虑的

按“投入产出比”排序，不是按酷炫程度：

1. **按应用不同的阈值**：查资料用的应用给 10 分钟，纯娱乐给 3 分钟。
   `AppClassifier` 加一层“每应用覆盖设置”就能支持。
2. **导出 / 导入设置**：换机时不用重新勾一遍。JSON 文件导出即可，不需要云。
3. **工作日 / 周末不同时段**：`Schedule` 从单条扩成一周七条。
4. **按最近使用时长排序**：`UsageStatsManager.queryAndAggregateUsageStats`，
   把最常打开的排最前面——用户通常只需要勾 3 个应用。
5. **桌面小组件**：显示“今天被拦回来几次”。注意别让它变成新的焦虑来源。

**明确不做的事**：不做强制锁机、不做白名单绕过检测、不做云端同步、
不做账号体系、不接广告。这些都会把项目从“把选择权还给用户”变成“替用户做决定”。
