# 开发路线图

按“能在真机上用起来”倒推，不是按代码量排序。每个阶段结束都有一个可验证的东西。

---

## 阶段 0：把环境跑通（半天）

**目标：能看到一个装到手机上的 APK。**

1. `bash setup_toolchain.sh` 装 SDK + Gradle，或直接用 Android Studio 打开本目录。
2. `./gradlew assembleDebug`，把 `app-debug.apk` 装到手机。
3. 确认应用能开、能走完引导页、悬浮窗锚点能建起来（用 `adb shell dumpsys window | grep zhizhi` 看）。

**这一阶段最容易卡住的地方**不是代码，是 Android Studio 的 JDK 版本和 SDK 路径。
命令行构建的好处是这些都能一眼看见。

---

## 阶段 1：验证三个“系统会不会答应我”的前提（1 天）

**这一阶段不改功能，只做验证。** 三条都不成立的话，后面全是白做。

| # | 要验证的事 | 怎么验 | 不成立怎么办 |
| --- | --- | --- | --- |
| 1 | `startActivity(HOME)` 能不能把用户从别的应用踢出去 | 授权悬浮窗后，在卡片上点“我走神了，退出”，看是否回到桌面 | 退回“只用通知做兜底入口”，并把这一点写进 README |
| 2 | Android 15 上锚点窗口能不能让后台起前台服务成功 | `adb shell am force-stop` 后，用 `adb shell am broadcast -a android.intent.action.BOOT_COMPLETED` 触发开机自启 | 放弃开机自启，改为“每次打开应用时恢复”，并把 targetSdk 降回 34 作为临时方案 |
| 3 | 游戏启动后 1 秒内能不能识别到 | 打开王者荣耀，看 logcat 里 `FgTracker` 的输出时间戳 | 阈值/轮询节奏调到 1 秒固定，并接受“偶尔错过启动窗口” |

真机验收清单见 `docs/真机验收清单.md`。

## 阶段 2：把核心闭环做扎实（3–5 天）

功能骨架已经在本仓库里了。这个阶段要做的是**把它变成每天真的愿意开着的东西**：

* **分类页的可用性。** 现在需要用户一个个手动勾。可以加：
  按“最近 7 天使用时长”排序（`UsageStatsManager.queryAndAggregateUsageStats`），
  把最常打开的排在最前面——用户通常只需要勾 3 个应用就够了。
* **提醒卡片的位置。** 底部卡片在带手势条的机器上可能贴太近。需要真机调 `setMargins`。
* **误报处理。** 微信被归到“娱乐”是错的：用户很可能真的在回工作消息。
  考虑给卡片加第五个按钮“这个应用别管了”，一键加入忽略名单。
* **卡片上的文案。** 现在的四句话是照你的想法写的，用两周之后大概率会想改。
  把文案全部放在 `strings.xml` 里就是为了改起来不用碰代码。

---

## 阶段 3：让它抗得住日常（1 周）

这是开源工具和玩具的分界线。

* **电量实测。** `adb shell dumpsys batterystats --charged app.zhizhi` 对比
  开 / 关监测的一天耗电差异。目标：< 2%/天。
* **国产 ROM 的存活率。** 至少在小米、华为、OPPO、vivo 四家各测一台。
  这一步不通过，用户装完第二天就会发现它“不工作了”，然后差评。
  需要写一份“各家怎么开权限”的图文说明，比代码更重要。
* **多进程/多用户边界。** 工作资料（Work Profile）里的应用能不能被识别？现在不能，要在文档里说明。
* **时区与夏令时。** 学习时段用的是“当天第几分钟”，不吃时区；但跨日判定要在
  23:59→00:00 上实测一次。

## 阶段 4：发布（2–3 天）

1. 换掉 `applicationId`（现在是占位的 `app.zhizhi`）、应用名、仓库地址。
2. 生成正式签名密钥，**离线备份**。丢了就没法给老用户升级。
3. 补 `fastlane/metadata/android/zh-CN/images/phoneScreenshots/` 里的截图（至少 4 张：
   首页、分类页、提醒卡片、本地记录）。IzzyOnDroid 要求这个。
4. GitHub Release 打 tag 发布 APK。
5. 向 IzzyOnDroid 提 issue 申请收录：`https://gitlab.com/IzzyOnDroid/repo/-/issues`
6. 换打赏二维码。
7. 写一份“为什么不用无障碍权限”“为什么没有联网权限”的说明放在 README 顶部——
   这两条是这个项目最容易被误解、也最容易被信任的地方。

---

## 阶段 5：之后可以考虑的

按“投入产出比”排序，不是按酷炫程度：

1. **数据不落盘模式**：现在统计只记次数和总时长，已经足够克制。可以再加一个“连统计也不记”的开关。
2. **导出/导入设置**：让用户换机时不用重新勾一遍。JSON 文件导出即可，不需要云。
3. **按应用不同的阈值**：查资料用的应用给 10 分钟，纯娱乐给 3 分钟。
   `AppClassifier` 加一层“每应用覆盖设置”就能支持。
4. **工作日/周末不同时段**：`Schedule` 从单条扩成一周七条。
5. **桌面小组件**：显示“今天被拦回来几次”。注意别让它变成新的焦虑来源。

**明确不做的事**：不做强制锁机、不做白名单绕过检测、不做云端同步、
不做账号体系、不接广告。这些都会把项目从“把选择权还给用户”变成“替用户做决定”。
