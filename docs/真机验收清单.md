# 真机验收清单

代码能编译 ≠ 能用。下面每一条都需要在真机上手动走一遍并打勾。
建议至少两台机器：一台 Android 15（验证新限制），一台 Android 10–12（验证兼容分支）。

记录方式：`adb logcat -s MonitorService FgTracker OverlayController BootReceiver`

---

## A. 权限与启动

- [ ] **A1** 全新安装后，引导页三屏可以翻页，最后进入权限页
- [ ] **A2** 「使用情况访问」按钮跳到 `Settings.ACTION_USAGE_ACCESS_SETTINGS`，
      授权后回到应用，状态显示「已授予」
- [ ] **A3** 「悬浮窗」按钮跳到悬浮窗授权页，授权后状态更新
- [ ] **A4** 「通知」按钮在 Android 13+ 弹系统权限框；拒绝后主功能仍然可用
- [ ] **A5** 总开关打开时若缺少必需权限，会跳到权限页而不是直接启动服务

## B. 后台存活（最脆弱的一环）

- [ ] **B1** `adb shell dumpsys activity services app.zhizhi` 能看到 MonitorService
- [ ] **B2** 服务启动后 `adb shell dumpsys window windows | grep -i zhizhi`
      能看到一个 1×1 的 `TYPE_APPLICATION_OVERLAY` 窗口
- [ ] **B3** **Android 15**：`adb shell am force-stop app.zhizhi` 之后，
      `adb shell am broadcast -a android.intent.action.BOOT_COMPLETED`，
      服务能重新起来且 logcat 里**没有** `ForegroundServiceStartNotAllowedException`
- [ ] **B4** 服务在后台挂 30 分钟，不被系统杀掉（看 logcat 有没有重启痕迹）
- [ ] **B5** 手机重启后（开关打开的情况下）服务自动恢复
- [ ] **B6** 四家国产 ROM（小米 / 华为 / OPPO / vivo）各测一台，记录是否需要额外开关

## C. 识别准确性

- [ ] **C1** 打开小红书 → logcat `FgTracker` 在 2 秒内输出 `com.xingin.xhs`
- [ ] **C2** 切到桌面 → 前台包名变成桌面包名，计时停止
- [ ] **C3** 按下电源键锁屏 → 前台清空；解锁后 `seed()` 能恢复
- [ ] **C4** 停留在同一应用 20 分钟不动，计时**不会**被清零（这是最容易写错的一条）
- [ ] **C5** 打开通知栏再返回，计时不中断
- [ ] **C6** 分屏模式下记录实际表现（预期：可能只跟踪到其中一个，需要在文档里说明）

## D. 提醒卡片

- [ ] **D1** 娱乐应用连续使用满阈值后，卡片出现在设定位置（底部/顶部）
- [ ] **D2** 卡片出现时，底下的应用**没有**卡顿、没有暂停、没有失去输入焦点
- [ ] **D3** 四个按钮都能点，点击后卡片立刻消失
- [ ] **D4** 「已完成，退出」/「我走神了，退出」→ 是否真的回到桌面？
      **不管成功与否，都去「本地记录」页确认 `成功/尝试` 计数有变化**
- [ ] **D5** 「还在查，再给 5 分钟」→ 5 分钟后再次提醒（不是立刻）
- [ ] **D6** 「我正在做正事」→ 冷静期内不再提醒
- [ ] **D7** 回答「退出」之后如果继续留在该应用，10 分钟内不再被提醒
- [ ] **D8** 卡片出现时按返回键 / Home 键，应用和卡片各自的表现符合预期

## E. 游戏模式（断触是本项目的红线）

- [ ] **E1** 打开王者荣耀 → 卡片在**加载画面期间**出现，不是在局内
- [ ] **E2** 点「确定，开始玩」之后，整局**没有任何弹窗**
- [ ] **E3** 点「算了，退出」→ 是否回到桌面
- [ ] **E4** 局内触摸、技能释放完全正常（确认 `FLAG_NOT_FOCUSABLE` 的写法没有干扰输入）
- [ ] **E5** 原神（横屏 + 沉浸式）下同样验证一遍
- [ ] **E6** 如果某个游戏因为我们的窗口而暂停/黑屏，记录下来——这是要单独修的问题

## F. 休息计时器

- [ ] **F1** 设置 1 分钟休息，到点弹出「休息结束」
- [ ] **F2** 「再休息 5 分钟」→ 5 分钟后再次弹出
- [ ] **F3** 「回到学习」→ `breakEndsAtMs` 归零，不再重复弹
- [ ] **F4** 休息期间锁屏再解锁，计时不丢

## G. 时段与暂停

- [ ] **G1** 把时段设成 1 分钟后开始，到点后 logcat 显示轮询提速
- [ ] **G2** 时段外打开娱乐应用，**不弹**任何卡片
- [ ] **G3** 「暂时停止监测 30 分钟」→ 通知栏状态变化，期间不弹卡片
- [ ] **G4** 30 分钟后自动恢复
- [ ] **G5** 跨午夜的时段（如 22:00–02:00）在 00:00 前后判定正确
- [ ] **G6** 「开始」「结束」两列转盘能**上下滑动**，松手后吸附对齐，中间那行高亮
- [ ] **G7** 切到 12 小时制，时段文字显示成 `7:00 a.m. – 11:00 p.m.`；切回 24 小时制显示 `07:00 – 23:00`
- [ ] **G8** 12 小时制下滚动 a.m./p.m. 列，时间真的在上午/下午之间切换（不是只换了显示）
- [ ] **G9** 滚动转盘后退出首页再进来，时间保持不改（说明写盘成功，且没有被误改）

## G2. 服务与总开关的一致性

- [ ] **Z1** 权限齐全时打开总开关 → 状态显示「监测进行中」，不会在几秒后被自动关掉
- [ ] **Z2** 故意关掉「悬浮窗」权限后打开总开关 → 约 8 秒后总开关自动关闭，首页给出原因说明
- [ ] **Z3** 上一条发生后，诊断页能看到「总开关开着但服务未在运行，已自动关闭总开关」

## H. 隐私与合规

- [ ] **H1** `aapt dump permissions app-release.apk` 输出里**没有** `android.permission.INTERNET`
- [ ] **H2** 打开飞行模式，全部功能正常（这直接证明没有联网依赖）
- [ ] **H3** release APK 用 `apksigner verify --print-certs` 确认是正式密钥签的
- [ ] **H4** `aapt dump badging` 里没有 `android:debuggable` 或 `testOnly`
- [ ] **H5** 「本地记录」页点清空，数字确实归零

## J. 提醒没弹出来时的排查路径（先做这一组）

手机上：应用首页 →「诊断」。
电脑上：`adb logcat -s ZhiZhi`

- [ ] **J1** 诊断页「环境」里的四项权限状态与系统设置里看到的一致
- [ ] **J2** 打开「服务运行中」和「锚点窗口可见」，两者都应为「是」
      若锚点是「否」，说明 Android 15+ 的后台启动豁免不成立，开机自启会失败
- [ ] **J3** 点「测试提醒卡片（前台）」→ 卡片**应该在 1 秒内出现**，8 秒后自动消失
      —— 这一条不通过，说明是渲染或权限问题，不是"后台被拦截"
- [ ] **J4** 自检后的诊断记录里出现 `Card` 标签，且 `可见性实测` 那行的
      `attached=true visibility=0 size=WxH` 里 W 和 H 都 > 0
- [ ] **J5** 如果 J3 正常（前台能显示）但日常用起来不弹，则问题确实是
      "该 ROM 拦截后台悬浮窗"。此时**必须**能收到降级横幅通知，而不是什么都没有
- [ ] **J6** 「本地记录」页的「提醒卡片实际显示 / 降级为通知」两个数字之和
      应等于该时段的提醒次数。若降级数持续增长，把诊断记录截图提 issue
- [ ] **J7** `adb shell dumpsys window windows | grep -i zhizhi` 能列出
      `ZhiZhi 锚点` / `ZhiZhi 卡片` 两个窗口（窗口标题是故意设的，便于过滤）

## K. 耗电

- [ ] **K1** `adb shell dumpsys batterystats --charged app.zhizhi` 记录一天数据
- [ ] **K2** 与不开监测的一天对比，差异 < 2%
- [ ] **K3** 待机 8 小时（屏幕关闭），服务没有被系统降级/杀掉
